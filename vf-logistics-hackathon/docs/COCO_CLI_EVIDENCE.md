# Evidence of Cortex Code (CoCo) CLI Usage

**Judging Criteria §9(1)** requires that the Prototype be created *"including use of Cortex Code CLI."*

This document records concrete, verifiable work that was performed **through Cortex Code CLI sessions** rather than by hand. Each item lists what CoCo was asked to do, what it changed, and how a judge can verify the result independently in the Snowflake account.

---

## 1. Why CoCo CLI, not a SQL editor

The entire backend of this prototype — 20+ stored procedures, the orchestrator, the audit-log design, the Marketplace integration, and the Streamlit dashboard — was authored and debugged conversationally through CoCo CLI. CoCo was used as the primary engineering surface for four things a plain SQL editor cannot do well:

1. **Multi-object refactors** — changing a procedure and every caller/dependent object in one pass.
2. **Live diagnosis** — CoCo queried `ACCOUNT_USAGE`, `ERROR_LOG`, and `INFORMATION_SCHEMA` itself to find the cause of a failure instead of the developer guessing.
3. **Marketplace provisioning** — requesting and mounting a listing, then rewriting the dependent procedure to match the real remote schema.
4. **Prompt engineering against real data** — iterating an AI prompt and re-running it against actual staged PDFs until output was correct.

## 2. Verifiable engineering sessions

### 2.1 Fixed a broken sanctions-screening procedure against real Marketplace schema

**Problem:** `WORKFLOW_SANCTIONS_SCREEN` was written against an assumed column layout and failed once the real Marketplace listing was mounted.

**CoCo CLI actions:**
- Requested and mounted the free listing via CLI:
  ```sql
  CALL SYSTEM$REQUEST_LISTING_AND_WAIT('GZTSZ290BV255', 120);
  CREATE DATABASE SNOWFLAKE_PUBLIC_DATA_FREE FROM LISTING 'GZTSZ290BV255';
  ```
- Introspected the real table (`INTERNATIONAL_TRADE_ADMINISTRATION_EXPORT_SCREENED_ENTITIES_INDEX`) to discover the actual column names instead of assuming them.
- Rewrote the procedure's matching logic to the real schema.

**How a judge verifies:**
```sql
SHOW DATABASES LIKE 'SNOWFLAKE_PUBLIC_DATA_FREE';
SELECT COUNT(*) FROM SNOWFLAKE_PUBLIC_DATA_FREE.CYBERSYN.INTERNATIONAL_TRADE_ADMINISTRATION_EXPORT_SCREENED_ENTITIES_INDEX;
-- Sanctions screening runs against live third-party data, not a mocked list.
```

### 2.2 Diagnosed a silently suspended Cortex Search Service

**Problem:** `SEARCH_BILL_OF_LADING()` returned `error_code 399131 — Service suspended`. Project documentation incorrectly assumed a suspended Cortex Search Service auto-resumes on query.

**CoCo CLI actions:**
- Ran `DESCRIBE CORTEX SEARCH SERVICE` and identified `indexing_state = SUSPENDED` **and** `serving_state = SUSPENDED`.
- Proved the auto-resume assumption false by re-issuing the query and capturing the hard error.
- Resumed the service and re-ran the semantic search end-to-end to confirm the fix.
- Corrected the inaccurate claim in the test report.

**How a judge verifies:**
```sql
DESCRIBE CORTEX SEARCH SERVICE MENDIX_APP.AGENTS.BL_SEARCH_SERVICE;
-- If suspended (to conserve trial credits), resume before demo:
ALTER CORTEX SEARCH SERVICE MENDIX_APP.AGENTS.BL_SEARCH_SERVICE RESUME;
CALL MENDIX_APP.AGENTS.SEARCH_BILL_OF_LADING('high value shipment from Shanghai', 5);
```

**Key finding recorded for reviewers:** a suspended Cortex Search Service does **not** auto-resume on query — it raises a hard error. This is the kind of platform behaviour that only surfaces through live execution.

### 2.3 Built AI-generated compliance explanations, then caught the AI hallucinating

**Goal:** replace an unreadable raw-JSON column in the operator UI with a human-readable anomaly reason (`ALERT`, `ALERT_RESPONSE`) generated by `AI_COMPLETE`.

**CoCo CLI actions:**
- Retrieved the live DDL of `PROCESS_BL_DOCUMENTS()` to extract the exact validation rules already used for `CONFIDENCE_SCORE`.
- Added the two columns and wired AI generation into the pipeline procedure.
- **Caught two hallucinations by testing against real rows, not by assuming the prompt worked:**
  - The model flagged every 2026 date as a "future date" error, because it has no reliable notion of the current date.
  - The model flagged a valid `24.5 kg` weight as "unrealistically low", inventing a plausibility threshold that no rule specified.
- Rewrote the prompt to state the four validation rules verbatim and to forbid any additional judgment or reasoning output, then re-ran it across all rows until output matched the deterministic `STATUS`/`CONFIDENCE_SCORE` already computed by the pipeline.

**How a judge verifies:**
```sql
SELECT DOC_ID, STATUS, CONFIDENCE_SCORE, ALERT, ALERT_RESPONSE
FROM MENDIX_APP.AGENTS.BILL_OF_LADING_EXTRACTED
ORDER BY DOC_ID;
-- AI-written explanations agree exactly with the rule-derived STATUS for every row.
```

**Engineering point:** the value of the CLI here was the *verification loop* — generating AI output and immediately checking it against ground truth in the same session, which is how the hallucinations were found before they reached the demo.

### 2.4 Found and fixed the most serious logic flaw in the workflow: the AI decision was being ignored

**Problem found by reading the live DDL through the CLI:** `WORKFLOW_INVESTIGATE_ANOMALY` asked Cortex AI for a recommended action (BLOCK/ESCALATE/CLEAR) — and then threw it away. It returned the analysis in a JSON string but persisted nothing, and the orchestrator called `WORKFLOW_AUTO_REMEDIATE(alert_id, 'ESCALATE')` with a **hardcoded** action. Every alert was therefore escalated regardless of what the AI concluded, and `RESOLUTION_NOTES` recorded only the generic text `"Escalated to compliance team"`. The system looked autonomous but the AI had no influence on the outcome.

**CoCo CLI actions:**
1. Added `AI_RISK_ASSESSMENT`, `AI_RECOMMENDED_ACTION`, `AI_DECISION_REASON`, `AI_ANALYZED_AT` to `FRAUD_ALERT`.
2. Changed the AI prompt to require a machine-parseable tail (`DECISION: <...>` / `REASON: <...>`) and parsed it with `REGEXP_SUBSTR`, defaulting safely to `ESCALATE` (human review) if parsing fails.
3. Rewrote the orchestrator to read `AI_RECOMMENDED_ACTION` back from the table and pass **that** to the remediation step, and to write the decision and reason into `WORKFLOW_AUDIT_LOG`.
4. Rewrote `WORKFLOW_AUTO_REMEDIATE` so `RESOLUTION_NOTES` and the outbound notification carry the AI's actual reason.
5. Added a graceful `SKIPPED` path for runs where no HIGH-severity alert qualifies (previously the pipeline logged `SUCCESS` steps with null parameters).

**Then tested the fix and found a second, subtler problem.** With the decision now wired through, all seven sampled alerts still came back `ESCALATE` — the model was defaulting to the cautious middle option because the prompt gave it no quantitative basis to justify anything else. Re-running the same alerts against a rubric anchored in real statistics changed the outcome materially:

- Computed peer baselines from the dataset (median cost/kg `$0.2557`, p95 `$1.0692`, p95 charges `$7,831` across 10,010 shipments).
- Injected the shipment's own cost/kg, those baselines, and a live sanctions-list match count into the prompt.
- Gave explicit thresholds for each action and instructed the model not to default to `ESCALATE`.
- Moved the sanctions signal *before* the decision, which also corrected a logical ordering flaw (the pipeline previously screened for sanctions only *after* deciding what to do).

**Result — genuinely differentiated decisions:**

| Alert | Shipper | Cost/kg | AI decision | Reason given by the model |
|---|---|---|---|---|
| 310 | SUSPICIOUS TRADING CO | $0.7895 | **BLOCK** | Shell/front company naming, cost per kg over 3x peer median |
| 11 | Panasonic Vietnam | $0.2662 | CLEAR | Within normal ranges, no sanctions matches |
| 137 | Trung Nguyen Coffee | $0.2066 | CLEAR | Below median cost/kg, recognisable counterparties |
| 139 | Hoa Sen Group | $0.1983 | CLEAR | Below median cost/kg, clean screening |
| 218 | Vinamilk Co Ltd | $0.3959 | CLEAR | Normal economics, clean screening |
| 222 | Foxconn Vietnam | $0.2044 | CLEAR | Below thresholds, recognisable counterparties |
| 229 | Honda Vietnam | $1.0027 | CLEAR | Below p95, clean screening |

The blocked shipment's status in `BILL_OF_LADING` changed to `BLOCKED` with `FRAUD_CHECK_PASSED = FALSE`; the cleared ones to `FRAUD_CHECK_PASSED = TRUE`.

**How a judge verifies:**
```sql
SELECT ALERT_ID, SEVERITY, SHIPPER_NAME, AI_DECISION, AI_DECISION_REASON, ALERT_STATUS
FROM MENDIX_APP.AGENTS.V_AI_DECISIONS ORDER BY AI_ANALYZED_AT DESC;

-- and the reasoning recorded step-by-step:
SELECT STEP_ORDER, STEP_NAME, INPUT_PARAMS, OUTPUT_RESULT
FROM MENDIX_APP.AGENTS.WORKFLOW_AUDIT_LOG
ORDER BY EXECUTED_AT DESC LIMIT 5;
-- Step 2 records "AI decision=... | reason=..."; step 4 records "action=... (decided by AI)".
```

**Why this matters:** this is the difference between a demo that *looks* agentic and one that is. It was only found by reading the deployed DDL and testing the outcome distribution — not by reading the project's own documentation, which described the workflow as autonomous.

### 2.5 End-to-end orchestrator validation with live timing

**CoCo CLI actions:** executed the full orchestrator and read back the audit trail it produced, confirming all five steps and the recorded execution time.

```sql
CALL MENDIX_APP.AGENTS.WORKFLOW_FULL_PIPELINE_V2('AUTO');
-- {"workflow":"FULL_PIPELINE_V2","status":"COMPLETED","steps":5,"alert_id":310,
--  "ai_decision":"BLOCK","ai_reason":"...","execution_time_ms":13392,
--  "audit_trail":"WORKFLOW_AUDIT_LOG"}
```

Steps confirmed in order: `DETECT_ANOMALIES` → `AI_INVESTIGATE` → `SANCTIONS_SCREEN` → `AUTO_REMEDIATE` → `SAP_POST`.

### 2.6 Cost control and account hygiene through the CLI

Because the prototype runs on a $400 trial credit, CoCo CLI was used to audit and shut down background compute between working sessions:

```sql
SHOW TASKS IN SCHEMA MENDIX_APP.AGENTS;      -- verified all 7 tasks suspended
SHOW WAREHOUSES LIKE 'COMPUTE_WH';           -- verified auto-suspend at 60s
ALTER CORTEX SEARCH SERVICE MENDIX_APP.AGENTS.BL_SEARCH_SERVICE SUSPEND;
```

All seven scheduled tasks (`TASK_FRAUD_SCAN`, `TASK_PROCESS_NEW_BL`, `TASK_AI_EXPLAIN_ANOMALY`, `TASK_COMPLIANCE_CHECK`, `TASK_NOTIFY_HIGH_FRAUD`, `TASK_GENERATE_WEEKLY_INSIGHTS`, `TASK_REFRESH_PDF_URLS`) are intentionally left **suspended** between demos and can be resumed with `ALTER TASK ... RESUME` for autonomous operation.

### 2.7 Front-end integration debugging

CoCo CLI was also used on the client side of the prototype:

- Diagnosed why an inline PDF viewer worked in local preview but failed on the deployed Mendix cloud sandbox, by inspecting the packaged widget archives and confirming which static assets were missing after deployment — leading to the decision to drop third-party widgets in favour of the platform's native document viewer.
- Extended the Mendix data-source SQL (`AI_COMPLETE` + `PROMPT` + `TO_FILE` over a staged PDF) and validated it against real staged Bill of Lading documents before it was pasted into the low-code microflow.
- Removed a hardcoded service-account password from `CallCortexAgent.java`, replacing it with the `SNOWFLAKE_MENDIX_PASSWORD` environment variable (see `COMPLIANCE_CHECKLIST.md` §5(d)).
